# alred 0.2.0a12

`0.2.0a12` は、NX-OS の interface／NTP 判定修正と対象ホストの部分一致指定を追加する alpha release です。

## 主な変更

- `--target-hosts-match contains` を追加しました。`--target-hosts leaf,spine` と組み合わせると、hostname に `leaf` または `spine` を含む機器を選択できます。省略時は従来の完全一致を維持します。
- 対象ホストの照合を共通化し、収集・設定投入・保存・lab 操作に適用しました。部分一致の空入力・不一致は接続前に停止します。
- Health Check は初回収集前に解決済みホストを固定します。初回収集失敗後の retry、after、rollback でも対象の変化を検出します。
- `show interface` を収集し、物理 Ethernet の明示的な admin state を interface 判定に使用します。SFP 未装着の `xcvrAbsen` などから admin-up を推定しません。
- NTP の配布状態 `Disabled`／`No session` を未同期と誤認する不具合を修正しました。`show ntp peer-status` の選択 marker、stratum、reach に基づいて判定します。
- NTP の delay／VRF の連結表示に対応し、欠損・破損・重複のある証跡を `UNKNOWN` として扱います。NTP 必須時の異常判定を `FAIL` に統一しました。
- before の再実行と inspection の retry を修正し、失敗した試行で以前の成功済み成果物を上書きしないようにしました。
- profile 別のチェック一覧、command 出力の解析箇所、判定閾値、対象ホスト指定の使用例をマニュアルに追加しました。

使用方法は[対象ホストの指定](../manual/common/TARGET_HOSTS.md)、チェック内容は
[profile ガイド](../manual/network-ops/03_PROFILE_GUIDE.md)から参照できます。

## 互換性と移行

- `--target-hosts` の既定は完全一致です。部分一致は `--target-hosts-match contains` を明示してください。文字列はカンマ区切りの OR 条件で、大文字・小文字を区別します。
- `network-baseline-nxos` は version `1.9`、NX-OS parser は `1.22`、Snapshot Builder は `1.4` です。
- 固定済みの古い profile に `show interface` を自動追加しません。新しい取得 command を使う場合は新規 before または明示的な profile revision が必要です。
- 古い execution context は引き続き読み取れます。新 context では実際の対象を保存し、直接収集の対象が 0 件の場合は開始しません。
- 旧 parser が失った NTP peer 行は元 raw の再 import が必要です。配布状態だけから時計の同期を推定しません。

## 配布対象

- SHA-256 checksum: `alred-linux-x86_64-glibc217.sha256`

## 検証結果

- `pytest -m "not device"`: 888 件成功。
- Ruff、CLI help、ドキュメントのリンク確認: 成功。
- Python 3.11 の native build と glibc 2.17 向け build: 成功。
- native binary と glibc 2.17 環境内の配布 binary で、`--version`／`--help`、部分一致 option の help、bundled sample 生成、inventory／license の解析を確認しました。
- synthetic transcript で、SFP 未装着かつ admin-down の interface と、配布停止中でも正常な peer が選択されている NTP が、ともに `PASS` になることを binary で確認しました。
- 配布 binary の SHA-256 checksum 照合: 成功。

## 既知の制約

- alpha project です。今回の変更について、実機接続・設定投入を伴う検証は実施していません。
- `show interface` による admin state の補完は物理 Ethernet／breakout が対象です。証跡がない場合は推定せず `UNKNOWN` とします。
- NTP の同じ remote address が複数 VRF に現れる場合は `UNKNOWN` とします。
- OSPF／vPC／BGP の一部の証跡不足判定、interface error の reset 識別など、既存の未実装部分は残っています。
