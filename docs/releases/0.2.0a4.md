# alred 0.2.0a4

`0.2.0a4` は、NX-OS の Health Check に hostname identity、interface 利用率、dynamic BGP
neighbor range の判定を追加し、接続先の取り違え防止と `write-memory` の実行結果を改善する
alpha release です。実機の show output に対する parser の堅牢性と、解析根拠を追跡するための設計・test
fixture も拡充しています。

## 主な変更

### Health Check

- inventory hostname と `show version` の `Device name` を照合する `hostname_identity` を追加しました。
  不一致は `FAIL`、取得・解析不能は `UNKNOWN` とします。
- `show interface counters table` の input／output rate と利用率を解析し、operational-up の Ethernet／
  port-channel を判定する `interface_utilization` を追加しました。既定閾値は 50% で `INFO`、70% で
  `WARN`、90% で `FAIL` です。
- C9300v の `Intvl`／`Rx`／`Tx` 形式と、従来の `Interval`／`InRate`／`OutRate` 形式、方向別の
  load interval、interface 略称の照合に対応しました。
- running config の IPv4／IPv6 dynamic BGP neighbor range と BGP summary を照合する
  `bgp_dynamic_neighbor_health` を追加しました。range 内に peer が 0 件の場合は `WARN`、before に
  存在した peer が after で 0 件になった場合は regression として `FAIL` にします。
- `network-baseline-nxos` の対象 platform を NX-OS に限定し、Arista EOS などへ NX-OS profile を
  適用しないようにしました。
- `checklist.md` の `Started at`、`Completed at` に続けて、両時刻の差分を `Duration` として
  `HH:MM:SS` と総秒数で表示します。機器見出しには inventory の management IP も表示します。
- dynamic BGP prefix を含む Snapshot の JSON 保存時に network object を文字列へ正規化し、収集・解析後の
  serialization error で処理が停止する問題を修正しました。

### 接続先 hostname 保護

- SSH の接続確認で prompt hostname と inventory hostname を完全一致で照合します。
- NX-OS の既定 hostname `switch` は初期設定候補として警告し、read-only 処理は継続します。config 投入または
  save では、通常の実行確認とは別に対象 hostname／IP を表示して `yes` の確認を要求します。
- 既定 hostname 以外の不一致は対象から除外します。意図した不一致は
  `--allow-hostname-mismatch` を明示した場合だけ警告として継続できます。

### Direct Config Push と Save

- `write-memory` の失敗 host を `<hostname> (<management-IP>)` 形式で表示します。
- 実行結果の末尾に使用した log file の absolute path を表示します。既定は
  `logs/write-memory.log` です。
- NX-OS の `copy running-config startup-config` は従来どおり 180 秒待機し、自動 retry は行いません。
  host ごとの開始・完了時刻、経過秒、status、error を log へ記録します。

### 設計、fixture、開発規約

- config／show output を解析する機能について、入力 anchor、抽出 field、正規化、判定、欠損時動作、
  provenance、fixture を設計書へ残す repository instruction を追加しました。
- hostname、interface counters、IPv6 BGP summary、dynamic neighbor config の sanitized fixture と境界条件 test を
  追加しました。

## 互換性と移行

- 組み込み `network-baseline-nxos` profile は version `1.2` です。新しい check と field は既存 schema major
  version への追加であり、既存 field は維持します。
- 新しい判定により、以前は `PASS` だった環境でも実際の hostname、interface 利用率、dynamic BGP state に
  応じて `WARN`、`FAIL`、`UNKNOWN` になる場合があります。
- SSH prompt hostname の不一致は fail closed になりました。正当な alias などで不一致を許容する場合は、接続先を
  確認したうえで `--allow-hostname-mismatch` を明示してください。
- interface 利用率閾値は custom profile の `thresholds.interface_utilization` で変更できます。

## 対応範囲

- 主な開発・継続試験対象は Nexus 9000v／N9K-C9300V、NX-OS `10.5(4)` です。
- 実機を含む Cisco NX-OS／Nexus 9000 series は収集、Health Check、VNI 状態確認の利用対象ですが、
  設定投入可否は exact model、release、role、Capability の組み合わせで fail closed に判定します。
- N9K-C9336C-FX2、N9K-C93180YC-FX3、N9K-C9348GC-FX3、N9K-C9364C-H1 は公式資料と
  golden config による静的確認だけであり、`APPLY_VERIFIED` ではありません。

## 既知の制約

- 本バージョンは alpha です。未登録 model、release、role、Capability の設定投入は許可しません。
- EVPN Multi-Site と、その topology role としての `route-server` は未対応です。single-site の role sample には
  将来用の `route-server` 定義を先行追加していません。
- interface 利用率は device の load interval 内平均です。microburst、queue drop、buffer congestion を
  この値だけから判定しません。
- Nexus 9000v `10.4(5)M`、文書確認対象 hardware の実機、Multi-Site は動作検証対象外です。
- 標準 Release は Linux x86_64 glibc 2.17 binary だけです。glibc 2.28／2.34、Linux aarch64、
  Windows binary は本 Release に含めません。
- 自動 test では `device` marker を除外しています。実機操作は対象と許可を明示した受入試験として
  別途実施します。
