# 0.2.0a13

IPv4 / IPv6 Route Diff を追加する alpha（Pre-release）です。保存済みログの任意 2 時点を比較し、
CLI・オフライン HTML・Health Check で結果と取得証跡を確認できます。

## 追加した機能

- `route-diff-nxos` は 2 file、複数ログを含む before / after directory、Source Map に対応します。
  directory は prompt のホスト名で対応付け、子 directory は `--recursive` で指定します。
- `show ip route` / `show ipv6 route` の default・指定 VRF・全 VRF と、alred の全体収集ログを扱います。
- Prefix、Prefix + AD、Prefix + AD + Cost、Prefix + AD + NextHop、Prefix + AD + Cost + NextHop の
  5 方式で比較します。経過時間・表示順・空白・等価な IPv6 表記は経路差分に含めません。
- HMM と 1 行形式の VXLAN 属性を解析し、NextHop 比較では segment / tunnel / encapsulation も保持します。
- HTML は差分行のみを既定表示とし、共通行の表示、元ログの対象 route command 区間 / 入力全体の切替、
  検索・証跡への移動・レビュー記録の保存に対応します。長い証跡は初期状態で折りたたみます。
- JSON / CSV / Markdown / checklist とホスト別 HTML を生成します。未取得・不完全な解析は UNKNOWN とし、
  正常な空経路や全経路削除と区別します。
- 追加 Health profile `route-diff-nxos` で before / after / rollback に接続します。
  rollback では Cost や VXLAN 属性を含む復元漏れも判定します。Web UI サーバーは今回の対象外です。

## 利用例

```bash
alred route-diff-nxos \
  --before logs/before \
  --after logs/after \
  --input-format nxos-transcript \
  --output-dir review-01/route_diff
```

操作方法は [画像付きユーザマニュアル](../manual/network-ops/13_ROUTE_DIFF_GUIDE.md)を参照してください。

## 性能の対象範囲

**before / after 各時点で 1 万 route まで**を今回の対象とします。
全入力の host / VRF / AF ごとの prefix 件数を合計します。ECMP path 数や両時点の合計ではありません。
1 万 route 超は対象外であり、10 万 / 100 万 route は将来拡張です。
CLI に件数による拒否・切り捨ては追加していません。画面の filter は解析量を減らしません。

1 万 route の代表ケースは全出力と HTML 操作を検証済みです。共有環境の 4 path・全変更ケースでは、
最大 RSS 約 2.2 GiB、全出力約 940 MiB を観測しました。時間・メモリ・容量は保証値ではなく、
path 数、差分率、非 route ログの量、実行環境で変わります。
[性能検証記録](../implementation/ROUTE_DIFF_PERFORMANCE_REPORT.md)を参照してください。

## NX-OS の検証範囲と制約

対象予定はトップ README の Nexus 機種と NX-OS 10.4(5)M 以降で、10.5(4) / 10.6(4)M を重点対象とします。
機種・release ごとの詳細 route fixture は不足しており、これらすべての組み合わせの動作確認済みを意味しません。
現時点の確認は合成 fixture と個別の保存済みログによる解析・比較です。
[対応状況](../design/network-ops/NXOS_CAPABILITY_AND_FIXTURE_MATRIX.md#10-route-diff-の追加対応範囲)を参照してください。

別行 VTEP を伴う形式など、未対応 grammar は UNKNOWN になります。重複取得を自動で選別せず、
入力の整理または Source Map の指定を案内します。Chromium で HTML の操作を確認済みです。

## 更新・再実行

parser / 正規化 / 比較の version が変わるため、旧 RouteSnapshot と新しい Snapshot を混在させず、
保存済みの before / after 両方の raw ログを新しい版で再解析してください。
以前の比較 fingerprint に対応するレビュー記録は引き継げません。
既存の成果物は保持し、出力先には新しい directory を指定します。

HTML には元入力の bytes を含みます。共有時は入力全体の内容を確認してください。
表示を対象 route command に絞っても、その他の command や機密情報を削除する処理にはなりません。
