# alred 0.2.0a5

`0.2.0a5` は、NX-OS Health Check と同時に機器一覧を Markdown／CSV で作成し、
environment alarm の原因と Nexus 9000 の transceiver 不在状態をより具体的に扱う
alpha release です。`show inventory` と `show license usage` の解析には、対象 command を
限定して NTC Templates／TextFSM を使用します。

## 主な変更

### Device Summary

- Health Check の phase ごとに `device-summary.md` と `device-summary.csv` を生成します。
- hostname、管理 IP、manufacturer、model、chassis serial number、OS 種別／version、
  license usage、topology role／function、host 別 Health 結果、収集状態、収集時刻を
  1 device 1 row にまとめます。
- Markdown と CSV は同じ canonical row、列順、hostname sort を使用します。
- vPC peer の推定は初期範囲に含めません。既存の `vpc_health` は変更しません。

### Inventory と license usage parser

- 組み込み `network-baseline-nxos` profile に `show inventory` と `show license usage` を
  optional command として追加しました。
- `cisco_nxos_show_inventory.textfsm` と `cisco_nxos_show_license_usage.textfsm` を使用し、
  NTC Templates／TextFSM version、template file 名、template SHA-256 を Snapshot に記録します。
- license usage は観測情報です。契約、entitlement、registration、authorization、
  compliance の判定や Health Result の正常性判定には使用しません。
- `show license all` は Device Summary profile の収集対象外です。既存の汎用
  `show_commands.example.txt` の内容は変更しません。

### Environment と interface status

- `environment_health` が `FAIL` の場合、power supply、redundancy、fan、temperature などの
  alarm 行を message に併記します。
- `show interface status` の `xcvrAbsen` と `xcvrAbsent` を、対応済みの transceiver 不在状態
  `sfpAbsent` へ正規化します。その他の未知 status は従来どおり fail closed で
  `Interface status could not be parsed` とします。
- `interface_health` を pilot とし、取得 command、parser anchor、canonical field、単体判定、
  before／after 比較、evidence、未実装範囲の記載形式を設計書に整理しました。

### Dependency と配布

- `ntc-templates>=9.0,<10` を direct runtime dependency として追加しました。
- PyInstaller binary に NTC Templates の data file と `THIRD_PARTY_LICENSES.txt` を同梱します。
- NTC Templates と TextFSM の Apache License 2.0 notice を追加しました。

## 互換性と移行

- 組み込み `network-baseline-nxos` profile は version `1.3` です。optional command が
  2 件追加されるため、新しい before 収集では `show inventory` と `show license usage` を
  実行します。既存 Operation の固定済み profile hash は書き換えません。
- Device Summary は新規追加成果物であり、既存の Snapshot、Health Result、Checklist、
  VNI map の field と file 名を変更しません。
- inventory／license の収集または解析に失敗しても、Device Summary は対象 device の row を
  残し、`UNKNOWN`、`not_collected`、`unsupported` などの状態を表示します。

## 対応範囲

- 初期 Device Summary parser の platform scope は Cisco NX-OS です。列名と canonical row は
  将来の他 OS adapter 追加を考慮していますが、他 OS parser は未実装です。
- N9K-C93180YC 系の sanitized synthetic fixture と NX-OS 9.x／10.x 相当の license output で
  parser と出力を検証しています。N9K-C93180YC 実機の raw output は repository に保存していません。
- 機器の設定投入可否は従来どおり exact model、release、role、Capability の組み合わせで
  fail closed に判定します。本変更は N9K-C93180YC の `APPLY_VERIFIED` 登録を追加しません。

## 配布物

- SHA-256 checksum: `alred-linux-x86_64-glibc217.sha256`

## 検証結果

- Python 3.11 の `pytest -m "not device"`: 565 tests passed
- `ruff check .`、CLI help／version、lock file、Markdown link／sample validation: PASS
- Python 3.11 native PyInstaller binary の version／help、NTC template／license notice の同梱: PASS
- 標準 Linux x86_64 glibc 2.17 binary は Release asset 作成時に検証します。
- 自動 test では `device` marker を除外し、sanitized fixture による parser／report test を
  実施します。

## 既知の制約

- 本バージョンは alpha です。未登録 model、release、role、Capability の設定投入は
  許可しません。
- license usage は契約や compliance の正常性判定ではありません。`show license all`、
  Smart Licensing の registration／authorization、license Health evaluator は未実装です。
- Device Summary の vPC peer 列と、LLDP からの vPC peer 推定は未実装です。
- primary chassis の serial number を一意に選択できない場合は推測せず `UNKNOWN` とします。
- 標準 Release は Linux x86_64 glibc 2.17 binary だけです。glibc 2.28／2.34、
  Linux aarch64、Windows binary は本 Release に含めません。
- 自動 test では `device` marker を除外しています。N9K-C93180YC 実機への接続・
  設定投入は実施していません。
