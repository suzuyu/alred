# alred 0.2.0a3

`0.2.0a3` は、実機の Health Check と収集結果を Portable Evidence Package として隔離環境へ搬送し、
Containerlab、ネットワーク構成図、AI 解析へ再利用する workflow を追加した alpha release です。
Overlay（VNI）変更と Direct Config Push についても、失敗証跡、接続保護、rollback 後の確認を強化しています。

## 主な変更

### Health Check と Operation

- `operations/live/YYYY/MM/DD/<change-id>` の日付階層と、正常に公開された最新 Operation を指す
  `operations/live/latest` を追加しました。
- `health-check before --purpose inspection` から、running config、LLDP、baseline、Overlay 状態を同じ
  attempt へ収集できるようにしました。
- NX-OS の interface `notconnec`／`notconnect`、NTP session、running-config diff、VNI／VRF／Gateway を
  Health Check の判定と成果物へ追加しました。
- command ごとの canonical file を収集時に生成し、従来の統合 show log は互換成果物として維持します。
- terminal Operation を deterministic `tar.gz` へまとめる手動の `operation archive` を追加しました。

### Portable Evidence Package

- `evidence-package create/inspect/verify/import` を追加しました。
- `digital-twin` と `ai-analysis` profile、開示 level、sanitized／verbatim config、Manifest、SHA-256、
  Secret Scan に対応しました。
- import 時に package と checksum を検証し、正常に import された最新 package を
  `imported-evidence/latest` から参照できるようにしました。
- running config、inventory、role、site、description rule、LLDP、canonical link evidence を隔離された
  consumer へ搬送できます。

### Containerlab

- Evidence Package から import、config 変換、link 正規化、Containerlab topology 生成までを行う
  `clab-set-cmds` を追加しました。
- 外部の running config directory を取り込む `import-running-config` と、Evidence Package を使わない
  Containerlab 生成経路を追加しました。
- `clab-transform-config` で management、AAA、NTP、lab user などを platform adapter と parameter file に
  基づいて lab-local 値へ変換できるようにしました。
- `clab-apply-config` は node の health と `startup-delay` を考慮し、strict CLI error、fail-fast、
  ignored error の前後 command context、attempt 証跡を保存します。
- 9000v の既定 topology では startup config を設定せず、node 起動後に config を投入する workflow としました。

### Topology と Network Diagram

- `generate-network-diagram` で Mermaid と draw.io を一括生成できるようにしました。
- Physical、Underlay、EVPN control plane、Overlay Service、VRF 単位の detail diagram を分離しました。
- Overlay Service diagram で VNI、VRF、Gateway、L3VNI mode、vPC shared VTEP、placement、
  Route Target と VRF 間 route leak を表現できるようにしました。
- Evidence Package、既存 Operation、外部 running config の各入力経路から link を正規化できます。

### Overlay Configuration

- `latest-known-good` が standalone Health Check の `WARN` を暗黙採用しないようにし、必要な場合は
  `--reference-operation-id` で明示選択できるようにしました。
- plan conflict 時に `conflict-report` の path を表示し、投入対象 config の path 表示を統一しました。
- rollback Health Check が既存 `WARN` だけの場合、raw／semantic config の復元を確認したうえで
  `overlay-change accept-rollback-state-warn` による明示承認を要求する workflow を追加しました。
- WARN acceptance は対象 attempt と verification artifact の hash へ固定し、stale／tampered evidence を拒否します。
- apply、save、rollback、save-rollback の partial attempt と失敗状態を不変の証跡として保持します。

### Direct Config Push

- `push-config`／`push-config-dir` の NX-OS CLI error 検出を既定で strict にしました。
- 限定した error だけを許容する YAML allowlist と、調査用途の非推奨
  `--ignore-all-cli-errors` を追加しました。
- `push-config-dir` は login user、`vrf context management`、`interface mgmt0`、`line vty` を
  既定で投入対象から除外し、`--force` を指定した場合だけ保護を解除します。
- CLI error 時に投入行番号、該当 command、直前 5 command を log と画面へ表示します。

### 文書と sample

- 設計書を `common`、`network-ops`、`containerlab`、`topology`、`development` に再編しました。
- README を概要と Quick Start への入口に整理し、Network Operations、Containerlab、Topology、
  Overlay Configuration、Direct Config Push の manual を追加・更新しました。
- Nexus 9000v の single-site Fabric sample と、Physical／Underlay／EVPN／Overlay Service の
  構成図 sample を追加しました。

## 互換性と移行

- `push-config`／`push-config-dir` は CLI error を既定で失敗として扱います。既知の無害な応答は
  allowlist で限定的に許容してください。全 error を無視する `--ignore-all-cli-errors` は非推奨です。
- `push-config-dir` の接続保護 filter は既定で有効です。保護対象を含む完全投入は、影響を確認して
  `--force` を明示した場合だけ実施できます。
- 新しい Operation は日付階層へ保存されます。既存の flat layout は resolver で読み取り互換を維持します。
- Evidence Package import は verify を内部で実施します。独立した `verify` は搬送前後の監査用途として利用できます。
- 既存の collect、Topology、Containerlab、VNI、config push CLI は維持します。

## 対応範囲

- 主な開発・継続試験対象は Nexus 9000v／N9K-C9300V、NX-OS `10.5(4)` です。
- 実機を含む Cisco NX-OS／Nexus 9000 series は収集、Health Check、VNI 状態確認の利用対象ですが、
  設定投入可否は exact model、release、role、Capability の組み合わせで fail closed に判定します。
- N9K-C9336C-FX2、N9K-C93180YC-FX3、N9K-C9348GC-FX3、N9K-C9364C-H1 は公式資料と
  golden config による静的確認だけであり、`APPLY_VERIFIED` ではありません。

## 検証結果

- Python 3.11 の `pytest -m "not device"`: 539 tests passed
- `ruff check .`、CLI help／version、lock file、Markdown link／sample validation: PASS
- Nexus 9000v／N9K-C9300V `10.5(4)` で Health Check、Overlay apply／save／rollback、
  running／startup config 復元を確認済みです。
- rollback 後の既存 `WARN` について、対象 evidence を表示した明示 acceptance と、未承認時の
  save-rollback 拒否を確認済みです。

## 既知の制約

- 本バージョンは alpha です。未登録 model、release、role、Capability の設定投入は許可しません。
- Nexus 9000v `10.4(5)M`、文書確認対象 hardware の実機、Multi-Site は動作検証対象外です。
- Canonical Link Evidence の Health Check compare 統合、Direct Config Push の immutable evidence／post-check、
  archive restore、全既存 schema の統合は未実装です。
- Overlay Service の保存済み `OverlayState` 直接 adapter と `sampled` verification は未実装です。
- 標準 Release は Linux x86_64 glibc 2.17 binary だけです。glibc 2.28／2.34、Linux aarch64、
  Windows binary は本 Release に含めません。
- 自動テストでは `device` marker を除外しています。実機操作は対象と許可を明示した受入試験として
  別途実施します。
