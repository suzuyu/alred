# alred 0.2.0a11

`0.2.0a11` は、Health Check の LLDP／description 判定を直接収集と `nxos-transcript` で共通化し、
SSH 収集の再試行範囲、EOS 対向 LLDP、判定対象 scope、および link mismatch report の比較根拠を
明確にする alpha release です。

## 主な変更

### Health Check の LLDP evidence と判定 scope

- `network-baseline-nxos` に `show lldp neighbors detail`を追加し、running config と同じ Snapshot 世代から
  Canonical Link Evidence、`LinkDiagnostics`、confirmed／candidate link を生成します。
- LLDP／running config の取得・parse・managed peer の逆方向 evidence を
  `lldp_evidence_completeness`、双方向 LLDP が成立した link の description 不一致を
  `lldp_description_consistency`へ分離しました。片方向または対象外 link を description 不一致として
  重複評価しません。
- server、inventory 未登録 endpoint、`wan-provider`などの外部回線、role 競合 host は Health 判定から
  除外し、Topology evidence には保持します。
- EOS host 自身へ NX-OS profile は適用しませんが、NX-OS link の対向 evidence として EOS 形式の
  `show lldp neighbors detail`を解析します。

### `nxos-transcript` の LLDP／running config 対応

- prompt 付きの `show lldp neighbors detail`と`show running-config`を Collection Manifest の command
  区間として固定し、`alred-collect`と同じ parser／normalizer／evaluator で評価します。
- LLDP または running config の欠落、取得失敗、CLI error、破損、曖昧な duplicate は正常と推測せず
  completeness を `UNKNOWN`にします。
- transcript は実際の command 取得時刻を保証しないため、`clock_health`を`NOT_APPLICABLE`にしました。
  `show clock`の parse 結果と provenance は保持します。

### SSH 収集と command artifact

- 直接 Health 収集は共通 connect-check を既定で実行し、確認後に 1 host につき 1 つの収集 session を
  確立して全 command で再利用します。通常は connect-check と収集の 2 session です。
- 最初の command 実行前の session 初期化失敗だけを、1 秒後に 1 回再試行します。command 送信後の
  timeout／CLI error／parser error は自動再試行せず、状態不明の session を再利用しません。
- LLDP は通常の command artifact を canonical source として保存します。`raw/lldp/`は既存 Topology
  consumer 向けの互換 mirror とし、同じ機器 command を再実行しません。
- `show-commands.txt`には LLDP を実行順で表示し、running config の base collection と
  `raw/config/`の保存先をコメント表示します。コメントは追加 command として実行されません。

### Link mismatch report の比較根拠

- `DESCRIPTION_NOT_RECIPROCAL`に期待する逆方向 claim と実際の逆方向 claim を追加しました。
- `mismatch-links.md`は診断に応じて A-side claim／LLDP observed、Expected reverse、Actual reverse、
  Difference を表示します。適用されない LLDP 欄を常に `-`で表示しません。
- description-only の有向 conflict は `Rendered as conflict claim`と表示し、検証済み link の描画と
  区別します。

## 互換性と移行

- `raw/config/<hostname>_run.txt|json`と`raw/lldp/<hostname>_lldp.txt|json`の既存 path は維持します。
  新規 Collection Manifest は LLDP command artifact を優先し、過去成果物だけ`raw/lldp/`へ fallback します。
- Health Check Profile `network-baseline-nxos`は version `1.6`、NX-OS parser は version `1.19`です。
- HealthSnapshot v1 の `link_evidence`、LinkDiagnostics v1 の逆方向 claim field は optional 追加です。
  既存成果物は引き続き schema-valid です。旧 LinkDiagnostics に比較 evidence がない場合、report は
  `not recorded in this artifact`と表示します。
- `lldp_description_consistency`だけを参照する consumer は、新しい`lldp_evidence_completeness`も確認して
  evidence 不足と実際の不一致を区別してください。
- `mismatch-links.md`の個別明細 label は変更されています。旧 label を文字列解析する処理は新しい比較項目へ
  移行してください。

## 既知の制約

- 本 version は alpha です。未登録 model、release、role、Capability の設定投入は許可しません。
- EOS 対応は NX-OS link の対向 LLDP evidence の解析であり、EOS host への NX-OS Health profile 適用を
  意味しません。
- transcript の `clock_health`は取得時刻を保証できないため評価しません。
- `Actual reverse: (none)`は、対向 description が存在しない場合と active description rule に一致しない場合の
  両方を含みます。`Difference`と running config を確認してください。
- 標準 Release は Linux x86_64 glibc 2.17 binary だけです。glibc 2.28／2.34、Linux aarch64、
  Windows binary は含めません。
- 自動 test では `device` marker を除外しています。実機への接続や設定投入は実施していません。
